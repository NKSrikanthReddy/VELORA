# Velora Medical Record Consolidation & Clinical Briefing API

Backend service built for the AI-Powered Medical Record Consolidation and Clinical Briefing System hackathon project.

## Tech Stack
- **Python 3.13 / FastAPI**
- **SQLAlchemy 2.x ORM**
- **Pydantic v2 & Pydantic-Settings**
- **Alembic Database Migrations**
- **JWT Authentication & Bcrypt Hashing**
- **Supabase Storage with Local Storage Fallback**
- **PostgreSQL / Supabase DB with SQLite Fallback**

---

## Quick Start Guide

### 1. Environment Setup
The repository comes pre-configured with local fallbacks. Copy `.env.example` to `.env`:
```bash
cp .env.example .env
```

### 2. Run Demo Seed Script
Populate the database with 1 fictional patient (`patient@demo.com`), 1 fictional doctor (`doctor@demo.com`), 7 fictional medical documents, timeline events, medications, lab results, summary, and Q&A history:
```bash
python scripts/seed_demo.py
```

### 3. Start the FastAPI Development Server
```bash
uvicorn app.main:app --reload --port 8000
```

Access the interactive API documentation at:
- **Swagger UI**: [http://localhost:8000/docs](http://localhost:8000/docs)
- **ReDoc**: [http://localhost:8000/redoc](http://localhost:8000/redoc)

## Security & Patient Isolation
- **Role-Based Access Control**: `patient`, `doctor`, `admin`.
- **Strict Patient Ownership**: Patients can only query their own data.
- **Cryptographic Access Codes**: Temporary access codes (`MED-XXXXX`) generated by patients for doctor authorization.
- **Instant Access Revocation**: When a patient revokes access (`DELETE /api/patients/{patient_id}/access/{access_id}`), doctor authorization is terminated immediately.
- **Scoped Q&A Context**: The LLM never determines patient authorization; the backend strictly filters and isolates records to the authorized patient before sending context to the Q&A service.
- **Medical Advice Safety Boundaries**: Answers are strictly factual summaries from records; treatment advice and dosage recommendations are rejected by safety guardrails.
